# PHASE 11 — ADVANCED OBSIDIAN MEMORY RETRIEVAL

Use `MASTER_RULES.md`.

## Objective

Keep Obsidian as canonical data while making retrieval scale beyond naive recent/keyword scans.

## Requirements

- canonical Markdown remains Obsidian
- retrieval index is derived/rebuildable
- support exact/keyword retrieval first
- add semantic/hybrid retrieval only where supported and justified
- note freshness/change detection
- bounded context injection
- source/path metadata

Do not make the derived index authoritative.

## Acceptance

Changing an Obsidian note eventually changes retrieval results without creating a second canonical store. Retrieval traces show which notes influenced the answer.
