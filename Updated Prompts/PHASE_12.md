# PHASE 12 — OBSIDIAN SKILLS + CONTROLLED LEARNING

Use `MASTER_RULES.md`.

## Objective

Allow JARVIS to improve reusable procedures without uncontrolled self-modification.

## Flow

Observed successful workflow
→ candidate skill improvement
→ human-readable diff/proposal
→ JARVIS confirmation
→ write SKILL.md into Obsidian
→ verify
→ Hermes can discover the new version

Never let model output silently modify skills.

## Requirements

- skill metadata/version
- safe diff preview
- rollback/version history where practical
- verification after write
- provenance for why a change was proposed

Do not implement autonomous unrestricted skill mutation.

STOP.
