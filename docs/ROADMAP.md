# JARVIS Roadmap

The master sequence lives in `JARVIS_MASTER_PROMPT.md`. This summary preserves the phase boundary.

1. **Visual shell** — implemented and verified: layout, state-driven core, sample activity/results, settings, debug shell, and responsive behavior.
2. **Agent provider** — implemented and verified: provider abstraction, Command Code headless provider, structured responses, streaming, failures, timeouts, and cancellation.
3. **Tool registry** — implemented and verified: generic application-owned `ToolRegistry`, typed `JarvisTool` contracts, schema validation, demo tools, tool lifecycle events, and bounded execution loop.
4. **Obsidian** — implemented and verified: server-side vault config, path containment, `search_vault`, `read_note`, and safe `create_note` write boundary.
5. **Skills** — implemented and verified: runtime skill/process system (`SkillRegistry`, `loadSkillsFromDirectory`, `selectSkill`), 5 core skills (`meeting-prep`, `morning-briefing`, `capture-note`, `research`, `loose-ends`), lifecycle events, and truthful handling of unavailable future tools.
6. **Google Workspace** — implemented and verified: safe GWS CLI wrappers, 5 read-only tools (`search_gmail`, `read_gmail`, `get_calendar_events`, `search_drive`, `read_drive_file`), untrusted data security, skill integration, and health checks.
7. **Memory** — implemented and verified: local-first persistent SQLite memory (`node:sqlite`), 4 memory tools (`search_memory`, `store_memory`, `list_memory`, `delete_memory`), explicit authorization policy, secret rejection, bounded untrusted data injection, and inspection API.
7.5. **Local Ollama Provider** — implemented and verified: local Ollama as a second selectable reasoning provider (`OllamaProvider`), model auto-discovery, tool-calling adapter, and provider selection while keeping ToolRegistry, skills, memory, and UI completely provider-independent.
8. **Voice** — implemented and verified: fully local voice interface using local Whisper/whisper.cpp for speech-to-text and local Kokoro for text-to-speech. Project-local runtime (`.jarvis/voice/`), models, and management scripts (`start-voice.ps1`, `stop-voice.ps1`) installed and verified end-to-end. Features ephemeral in-memory audio privacy, real-time barge-in, unified `submitAgentRequest` submission seam, accessible microphone controls, and zero cloud speech dependencies.
9. **Write actions** — implemented and verified: application-owned confirmation lifecycle, in-memory `ConfirmationService` (single-use, 60s TTL replay protection), three write tools (`create_note`, `create_google_doc`, `draft_email` [strictly draft only, zero send_email capability]), UI Confirmation Card with accessible Confirm/Cancel actions, voice affirmation/cancellation matching, and server-side execution via `/api/agent/confirm`.
10. **Verification** — implemented and verified: formal application-owned task verification lifecycle (`queued` → `planning` → `executing` → `waiting_for_approval` → `verifying` → `completed` | `failed` | `cancelled`), tool-specific verification strategies (`create_note` vault containment and file check, `create_google_doc` doc ID & link validation, `draft_email` draft-only verification), application ownership enforcing that natural language output ("verified: true") is never proof, stale run rejection, and cancellation preservation.
11. **Observability** — implemented and verified: canonical Zod diagnostic contracts (`src/lib/contracts/diagnostics.ts`), server-side in-memory `DiagnosticService` (bounded 50 runs, 200 events, 50 voice entries), real execution timings (`performance.now()`), finite application-owned failure classification, strict browser sanitization boundary (redacting secrets, paths, GWS commands, audio), and read-only Debug Shell (`/debug`) displaying the complete 8-stage lifecycle pipeline (`RUN` → `PROVIDER` → `SKILL` → `TOOLS` → `CONFIRMATION` → `VERIFICATION` → `VOICE` → `FINAL RESULT`).
12. **Reliability and polish** — implemented and verified: latency hardening (disabling Turn 2 thinking and setting 15m keep-alive, reducing simple read latency by ~93%), deterministic task fast-path (<10ms resolution for unambiguous time queries), natural multi-turn conversation support with card context enrichment (`formatAssistantTurn`), tool argument coercion (`z.coerce.number()`), vault reading resilience with extension normalization and basename fallback, robust card and state normalization, non-blocking asynchronous voice playback, and comprehensive test coverage (66 suites, 389 tests).

Phases 1 through 12 are implemented and verified. Future phases after Phase 12 are NOT implemented. Later phases represent future roadmap items, not active working functionality.
